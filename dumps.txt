> Este cambio requerirá borrar (o reconfigurar) tus arenas actuales, ya que el formato de guardado de los kits en `arenas.yml` cambiará de un solo texto (`kit: Default`) a una lista (`kits: [Default, Nodebuff]`).

# Arquitectura de Múltiples Kits por Arena Completada

El sistema base del plugin de duelos ha sido reprogramado exitosamente para permitir **múltiples kits por arena** y un proceso de selección a través de GUIs, de la manera exacta en la que lo solicitaste.

## Cambios Principales Implementados

### 1. Modelo de Datos de Arenas Actualizado
- Modifiqué `Arena.java` y `ArenaManager.java` para que cada arena ahora posea una **Lista de Kits** en lugar de uno solo.
- **Sistema Legacy Compatible:** Si las arenas antiguas todavía tienen guardado `"kit: Nodebuff"` en `arenas.yml`, el plugin lo leerá automáticamente y lo migrará a la nueva estructura de listas, por lo que **no perderás nada de tu configuración previa**.

### 2. Nuevo Editor Multi-selección de Kits (`ArenaKitsGUI.java`)
Cuando usas el menú de edición de arenas (`/arena edit` -> Clic en **KIT**) o ejecutas `/arena set <arena> kit`, en lugar de dejarte elegir un solo kit y cerrar la ventana, se abrirá la nueva interfaz de edición:
- Puedes hacer clic izquierdo en varios kits para **seleccionarlos/deseleccionarlos**.
- Una vez elijas todos los kits que quieres permitir en tu arena, le das clic al panel verde `CONFIRMAR` que aparece en la fila de abajo y guardará los cambios.
- Ahora el comando `/arena list` muestra todos los kits soportados separados por comas.
- **Totalmente Editable:** Se ha añadido el archivo `plugins/Versus/menus/arena_kits.yml` para que puedas traducir o modificar todos los colores, materiales, lores y nombre del menú del editor.

### 3. Flujo Interactivo de Duelos (GUI Secuencial)
Al escribir `/duel <jugador>`, el jugador ahora pasa por dos pantallas gráficas sin escribir nada:
1. **Selección de Arena (`ArenaSelectionGUI.java`)**: Se abre un menú mostrando todas las arenas disponibles.
    - Si el jugador hace clic en "Random Arena", el sistema avanzará a seleccionar un kit, y luego buscará cualquier mapa aleatorio compatible con ese kit.
    - Si hace clic en un mapa en específico, avanzará filtrando los kits a *solamente* los que esa arena soporte.
    - **Totalmente Editable:** Se ha añadido el archivo `plugins/Versus/menus/arena_selection.yml` para que modifiques todos los nombres, descripciones y el botón de Random Arena a tu gusto.
2. **Selección de Kit (`KitSelectionGUI.java`)**: Se abre el menú de kits estándar, pero filtrado. Solo mostrará los kits correspondientes.
3. Al confirmar el kit, ¡se envía la notificación al rival!

### 4. Menú de Recompensas Mejorado
- He verificado el menú de recompensas (`rewards_menu.yml`). Ya está configurado con la variable `{expires_in}` en el lore por defecto para decirte "cuánto falta para que expire".
- El formato de tiempo ahora se puede editar bajo la sección `time-formats:` en `rewards_menu.yml` (puedes cambiar los prefijos de días, horas y minutos).

### 5. Reparación de Fallos de Compilación
Al hacer que el kit forme parte de la ecuación a la hora de mandar la `Request`, tuve que actualizar el sistema de *Party Duels* (`/duel <party>`), las subastas (*Betting*) y la generación interna del Duelo para que **siempre registren y entreguen el kit correcto al iniciar la partida**, evitando errores y pérdida de inventarios en el juego. Todo el código fue recompilado sin errores.

# Resumen: Sistema de Estadísticas con Base de Datos H2

- Ya no dependerás de archivos `.json` lentos para las estadísticas. Todos los datos de los jugadores se almacenan instantáneamente en una tabla SQL ultrarrápida.

### 2. Sistema de Estadísticas
Cada jugador ahora tiene registro de:
- Victorias
- Derrotas
- Racha Actual (Current Streak)
- Mejor Racha Histórica (Best Streak)

### 3. Anuncios de Rachas y `config.yml`
Se implementó la lógica en el `DuelManager` para que al finalizar un duelo se actualicen las rachas. Además, agregué estas líneas a tu `config.yml` (bajo `dueling.announcements`):
```yaml

    streak_broadcast_enabled: true
    #The minimum streak to broadcast
    streak_broadcast_minimum: 5
    #The interval to broadcast (e.g. every 5 wins)

Con esta configuración, si un jugador gana su quinto duelo seguido, el servidor entero verá el anuncio, y volverá a anunciarse cuando llegue a 10, 15, etc.

Agregué el nuevo comando `/duel stats [jugador]`. Cualquier jugador (o la consola) puede usarlo para ver su ratio W/L, rachas y más. Funciona de manera asíncrona cargando los datos desde la base de datos H2.

 Mejor Racha: 12
-------------------------------------
```

# Implementación de Duelos Grupales (Parties)

El objetivo es añadir la capacidad de hacer duelos en grupo (2v2, 3v3, etc.) mediante un sistema de "Parties" y un nuevo comando `/duelgroup`. Este es un cambio arquitectónico masivo, ya que el plugin fue diseñado originalmente solo para 1v1.

## Cambios Propuestos

### 1. Sistema de Parties (`Party` y `PartyManager`)
- **`Party`**: Una nueva clase que representará a un grupo. Tendrá un líder (`UUID`) y una lista de miembros (`List<UUID>`).
- **`PartyManager`**: Gestionará qué jugador está en qué grupo, creaciones, invitaciones pendientes y disoluciones.

### 2. Comandos (`/duelgroup`)
Se implementará el comando principal `/duelgroup` (o un equivalente) con los siguientes subcomandos:
- `create`: Crea una nueva party.
- `invite <jugador>`: Invita a alguien a tu party.
- `accept` / `decline`: Responde a una invitación de party.
- `disband` / `leave`: Elimina la party o la abandona.
- `duel <jugador>`: El líder solicita un duelo al líder de otra party.
- `acceptduel` / `declineduel`: Responde a la solicitud de duelo de otra party.

### 3. Modificación del núcleo de Duelos (`Duel` y `DuelManager`)
- **`Duel.java`**: Actualmente rastrea un `player1` y un `player2`. Se modificará para rastrear `team1` (`List<Player>`) y `team2` (`List<Player>`).
- **Finalización de Duelo**: El código que otorga recompensas, reproduce música y actualiza estadísticas ahora iterará sobre todos los miembros del equipo ganador y del equipo perdedor.
- **`DuelManager.java`**: Ahora vinculará a todos los jugadores de ambos equipos a la misma instancia de `Duel`. Si algún jugador se desconecta, se le dará de baja (o perderá automáticamente). Si todo el equipo muere o se desconecta, el equipo contrario gana.

### 4. Sistema de Peticiones de Grupo (`GroupRequestManager`)
- Crearemos un gestor paralelo a `RequestManager` (o lo unificaremos) para manejar peticiones donde el "Solicitante" y el "Solicitado" son `Parties` enteras.

### 5. Spawn en Arenas
- Todos los miembros del equipo 1 aparecerán en `spawnLocationOne` y los del equipo 2 en `spawnLocationTwo`. Si es necesario, añadiremos un pequeño "spread" (separación de bloques) para que no aparezcan exactamente en las mismas coordenadas y se asfixien o se empujen.

# Resumen de Cambios: Sistema de Apuestas Avanzado y Teletransporte

He completado exitosamente la implementación del sistema avanzado de apuestas y las mejoras de sincronización en los duelos.

## Cambios Realizados

### 1. Visibilidad en el TAB y PlaceholderAPI
- **Visibilidad:** Se modificó `ArenaVisibilityManager` para asegurar que los jugadores en duelo sigan siendo visibles en el TAB para todo el servidor, sin ocultarse. Los jugadores que estén de espectadores tampoco interferirán con la lista de jugadores.
- **PlaceholderAPI:** Se agregó y registró la variable `%versus_in_duel%` a través de la expansión `VersusPlaceholderExpansion`. Cuando un jugador está en un duelo, esta devolverá "En Duelo", y cuando no, devolverá nada (vacío), permitiéndote usarlo en el TAB o Scoreboard.

### 2. Sincronización de Salida (Teletransporte)
- En `DuelManager.java`, modificamos el flujo de finalización de duelos (`renderWinEffects`).
- Anteriormente, el jugador ganador se quedaba en la arena esperando mientras los fuegos artificiales se reproducían, y el perdedor regresaba.
- Ahora, **tanto el ganador como el perdedor son teletransportados a sus ubicaciones de retorno de manera sincronizada inmediatamente al acabar el duelo**, y los fuegos artificiales de victoria del ganador se reproducen en su ubicación de retorno en lugar de en la arena.

### 3. Sistema Avanzado de Apuestas (Interfaz Gráfica)
- **Modificación del Comando:** Se simplificó `/duel <jugador>` para que envíe la solicitud de inmediato (sin preguntar cantidad).
- **Interfaz (Trade Menu):** Cuando el jugador objetivo acepta el duelo usando `/duel accept`, **se abre un menú tipo Trade para ambos jugadores** (`BettingGUI`).
- **Funcionalidades del menú:**
  - **Dinero:** Puedes hacer clic en el lingote de oro para sumar ($100) o restar ($100) tu apuesta.
  - **Experiencia:** Puedes hacer clic en la botella de experiencia para sumar (1 nivel) o restar (1 nivel) tu apuesta.
  - **Ítems:** Puedes arrastrar hasta 22 ítems desde tu inventario a la interfaz. Si un ítem está en la `bet_blacklist` (lista negra de config), no te dejará meterlo.
  - **Visibilidad Compartida:** Verás tus puestas a la izquierda, y las del rival a la derecha. 
  - **Botón de Listo:** Debes colocar al menos algo de dinero, experiencia o ítems, de lo contrario no podrás darle al botón de "Listo". 
  - Una vez que ambos le dan a Listo, la GUI se cierra, se descuentan las cosas y **comienza el duelo**.
  - Si alguno cierra el menú antes de estar listos, el duelo se cancela y todo es reembolsado inmediatamente.
- **Entrega de Recompensas:** Al terminar el duelo, el ganador recibe en su inventario o suelo los ítems, y la suma total del dinero y XP apostado de forma instantánea.

> [!TIP]
> Puedes configurar los ítems prohibidos en el archivo de configuración dentro de `dueling.bet_blacklist` usando los nombres de materiales (ej. `BEDROCK`).

## Tabla H2: `duel_rewards`

```sql
CREATE TABLE IF NOT EXISTS duel_rewards (
  id          INTEGER PRIMARY KEY AUTO_INCREMENT,
  winner_uuid VARCHAR(36) NOT NULL,
  loser_uuid  VARCHAR(36) NOT NULL,
  timestamp   BIGINT NOT NULL,
  items_json  TEXT,
  money       DOUBLE DEFAULT 0,
  xp          INTEGER DEFAULT 0,
  claimed     BOOLEAN DEFAULT FALSE
);
```

## Anti-Dupe

- Al hacer click en "Reclamar":
  1. `UPDATE duel_rewards SET claimed=true WHERE id=? AND winner_uuid=? AND claimed=false` — si `rowsAffected == 0`, ya fue reclamada, no dar nada.
  2. Solo si `rowsAffected == 1` se entregan los ítems/dinero/XP.
- Esto previene doble-click o exploits de lag.
